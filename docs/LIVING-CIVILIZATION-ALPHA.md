- an advanced Worker runtime with tested GC1–GC8 and GC10 slices plus diplomacy and access policy;
- complete v0.1–v0.7 offline conformance and research packages;
- an official external agent client and hosted multiplayer contention contracts;
- accepted subsystem specifications and RFCs for the implemented slices.

[`current-state.v1.yaml`](../specs/current-state.v1.yaml) records which plane each capability occupies. “Implemented” never silently means “live in the production alpha.”

## Campaign doctrine

1. **Integrate before inventing.** Existing implementation is composed and exercised before new mechanics are authorized.
2. **Promote by evidence.** A capability moves from `IMPLEMENTED_RUNTIME` to `LIVE_HOSTED` only after production-like acceptance evidence.
3. **Preserve the frozen alpha.** Promotion uses an explicit successor/cutover decision. It does not mutate Perihelion Genesis, seal, room bound, or history in place.
4. **Exercise real external agents.** Synthetic unit coverage remains necessary but is not the campaign outcome.
5. **WATCH is an acceptance surface.** Existing world behavior is not product-complete unless humans can understand consequential change without hidden state.
6. **Research follows meaningful play.** Hosted STUDY remains blocked until natural multi-agent play produces evidence worth testing.
7. **No breadth by proxy.** RFC count, module count, and conformance totals do not substitute for integration evidence.

## Milestones

### LCA-0 — Baseline and promotion map

**Status:** COMPLETE

Reconcile the frozen production alpha, advanced Worker runtime, offline reference runtime, accepted specifications, and deployment evidence. Produce the direction package and identify the exact successor cutover boundary.

### LCA-1 — Advanced-runtime integration baseline

**Status:** ACTIVE_INTEGRATION. Gate A is not complete. Candidate evidence: Noema PR #551 and Noema PR #552.

Run the existing advanced Worker suites as one integration baseline. Prove that the implemented GC systems share one coherent state, event, authority, projection, and recovery spine. Fix integration defects without adding semantic breadth.

Exit requires:

- full Worker test and typecheck pass on the candidate integration commit;
- no accepted-slice implementation disabled merely to make the suite pass;
- deterministic settlement and replay/recovery evidence for strategically durable state;
- an explicit list of remaining production-alpha deltas.

### LCA-2 — External Agent Player population

**Status:** BLOCKED by remaining LCA-2 prerequisites. Gate B candidate `lca2-gate-b-three-external-agent-population` is named, not open.

Use at least three independently controlled external Agent Players. Verify onboarding, orientation, reconnect, contention, and the existing action surface without private operator strategy instructions.

### LCA-3 — Existing-system civilization scenario

**Status:** BLOCKED by LCA-2

Compose already implemented mastery, resource pressure, trade, construction, social memory, institutions, communication, conflict/diplomacy, and recovery into one bounded scenario. The goal is to reveal integration and balance defects, not add a new subsystem.

### LCA-4 — WATCH legibility and endurance

**Status:** BLOCKED by LCA-3

Use existing WATCH projections and the minimum required projection corrections to make the scenario legible. Conduct four-hour and then 24-hour runs with restart/recovery evidence.

### LCA-5 — Successor cutover decision

**Status:** BLOCKED by LCA-4

Decide whether the integrated runtime is ready to succeed the frozen hosted alpha. The decision must name migration, rollback, seal/Genesis preservation, live-world compatibility, operator procedure, and public claims. Passing LCA-4 permits the decision; it does not force deployment.

## Explicitly deferred

Until LCA-5:

- new canonical Player verbs;
- new GC breadth not already implemented;
- external crypto settlement, wallets, token minting, or x402;
- v0.8 Phenomena implementation;
- new Genesis Profiles, Story Seeds, or live room-bound expansion;
- multi-world orchestration;
- infrastructure justified only by hypothetical scale.

## Work admission

A task enters this campaign only when it names:

- existing capability or integration edge being exercised;
- current implementation plane and evidence commit;
- milestone and blocker;
- user-visible or operational outcome;
- governing specifications and accepted RFCs;
- validation and production-like observation;
- public claim permitted after completion;
- explicit non-goals.

Unmapped feature work is not authorized campaign work.
