The campaign begins with:

- an advanced Worker runtime with tested GC1–GC8 and GC10 slices plus diplomacy and access policy;
- complete v0.1–v0.7 offline conformance and research packages;
- an official external agent client and hosted multiplayer contention contracts;
- accepted subsystem specifications and RFCs for the implemented slices.

[`current-state.v1.yaml`](../specs/current-state.v1.yaml) records which plane each capability occupies. “Implemented” never silently means “live in the production alpha.”

## Campaign doctrine

1. **Integrate before inventing.** Existing implementation is composed and exercised before new mechanics are authorized.
2. **Promote by evidence.** A capability moves from `IMPLEMENTED_RUNTIME` to `LIVE_HOSTED` only after production-like acceptance evidence.
3. **Preserve the frozen alpha.** Promotion uses an explicit successor/cutover decision. It does not mutate Perihelion Genesis, seal, room bound, or history in place.
4. **Exercise real external agents.** Synthetic unit coverage remains necessary but is not the campaign outcome.
5. **WATCH is an acceptance surface.** Existing world behavior is not product-complete unless humans can understand consequential change without hidden state.
6. **Research follows meaningful play.** Hosted STUDY remains blocked until natural multi-agent play produces evidence worth testing.
7. **No breadth by proxy.** RFC count, module count, and conformance totals do not substitute for integration evidence.

## Work admission

A task enters this campaign only when it names:

- existing capability or integration edge being exercised;
- current implementation plane and evidence commit;
- milestone and blocker;
- user-visible or operational outcome;
- governing specifications and accepted RFCs;
- validation and production-like observation;
- public claim permitted after completion;
- explicit non-goals.

Unmapped feature work is not authorized campaign work.
