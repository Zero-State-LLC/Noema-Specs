## Settled Draft selections

- [Registry model](../../specify/study-admin-ui/contracts-draft/api-proposal/IDENTITY-AUTHORITY-DESIGN.md): owner-authorized out-of-band seed/change/recovery, with no registry-configuration UI yet.
- [Account resolution](../../specify/study-admin-ui/contracts-draft/api-proposal/ACCOUNT-RESOLUTION-DESIGN.md): existing uniquely qualified eligible Account link only for initial management; missing, ambiguous or unavailable linkage refuses without implicit provisioning. The inspected combined offline binder also has Player/Controller/credential effects and is not a qualified hosted Account-only resolver. Canonical human onboarding and invitee-contact flows remain separate.
- [Same-actor binding](../../specify/study-admin-ui/contracts-draft/api-proposal/SAME-ACTOR-BINDING-DESIGN.md): one server-established relation between verified identity, qualified existing Account and that SAME actor's valid existing Admin admission. Unbound/shared legacy contexts and independently paired credentials refuse the new boundary; existing legitimate Admin, isolated Player-plus-Admin and device approval remain unchanged. Account equality alone does not prove one actor or one natural person.
- [Carrier](../../specify/study-admin-ui/contracts-draft/api-proposal/BINDING-CARRIER-DESIGN.md): server-side record plus opaque credential/reference, with authoritative revalidation per management request. The later explicit “do as recommended” selected this Draft model; the earlier form timeout remains unanswered history. No installed machine fields, accepted protocol, transport/crypto/lifetime/adapter or live session follows. The separate read-only study credential is unchanged.

These choices remain settled for Draft preparation, not installed runtime authority. Study membership is admin-invited, least-privileged and exact-study/world scoped; it neither grants nor removes separately legitimate Admin authority. Steward designation can be added later through the Admin interface.
