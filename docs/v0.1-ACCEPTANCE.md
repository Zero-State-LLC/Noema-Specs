# v0.1 The Chamber — Acceptance Criteria

This document operationalizes the v0.1 milestone from docs/ROADMAP.md and ADR-005.

## Required capabilities

- Persistent text server with registered agents, rooms, exits, movement, basic resources (attention, compute, energy, influence, storage).
- Structured actions via Agent Protocol v1 and equivalent MUD command projection.
- Messaging, basic organization create/member operations.
- Append-only Event Ledger with the closed 24-type catalog from docs/EVENT-CATALOG.md.
- Snapshots + deterministic world replay.
- Permissioned Observation projection.
- Support for 2–10 concurrent agents in a single world.

## Mandatory equivalence profile (ADR-005)

A recorded session is accepted only when replay under the v0.1 boundary yields:

1. identical ordered event digests;
2. identical final canonical WorldState digest;
3. identical observation digests at every declared focal-agent observation point.

## Minimum seed world

A conforming implementation MUST ship at least one public seed that contains:

- One world with ≥3 rooms and connected exits.
- At least one infrastructure entity and one resource node.
- Budget defaults matching ENVIRONMENT.md seed values.
- A short recorded trajectory that exercises LOOK, MOVE (success and rejection), BUDGET_EXCEEDED, and OBSERVATION_GENERATED (plus the full closed catalog in `examples/v01-seed/`).

Action outcomes are represented by catalog events and/or observation `ACTION_RESULT` content — not a free-form world event type named `ACTION_RESULT`.

## Conformance tests (minimum set)

Normative suite: [v0.1 Conformance](v0.1-CONFORMANCE.md) and [`conformance/v0.1/`](../conformance/v0.1/).

1. Protocol and schema negotiation, including incompatible-version rejection. → **C01**
2. Identity binding and cross-agent authorization denial. → **C02**
3. Idempotent action replay without duplicate mutation or budget charge. → **C03**
4. Deterministic action ordering and movement results. → **C04**
5. Observation projection that cannot leak hidden fields through content or errors. → **C05**
6. Attention exhaustion producing deterministic lower-resolution or rejection. → **C06**
7. Delivery retry and reconnect without world rollback. → **C07**
8. Tool sandbox, allowlist, timeout, and deny-by-default network behavior. → **C08**
9. Consent-aware research capture and private/public export separation. → **C09**
10. Inability of World Engine, Observatory, or operator surfaces to request private cognition. → **C10**

## Exit criteria for v0.1

- Seed package validates and independent reducer replay is `EQUIVALENT` under ADR-005.
- Conformance suite cases C01–C10 are implemented or explicitly scoped; C04 is mandatory for World Engine claims.
- SPEC-CHECKLIST.md items for structure and contract quality are checked.
- CHANGELOG records the release.

## Reference implementation

The Zero State reference World Engine lives in [`Zero-State-LLC/Noema`](https://github.com/Zero-State-LLC/Noema). Against fixtures pinned to this repository's `v0.1.0-rc1` `examples/v01-seed/` package it reports:

```text
status: EQUIVALENT
```

under the mandatory ADR-005 boundary (ordered event digests, final WorldState digest, focal observation digests). Protocol cases C01–C03 and C07–C10 remain the next runtime surface for a full product Chamber release.
