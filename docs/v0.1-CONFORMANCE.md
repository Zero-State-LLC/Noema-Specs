## Family notes (C11–C17)

### C11 — Human onboarding

Atomic expectations: PLAY / CONNECT AGENT / WATCH present; Chamber reachable without extensive docs; no provider credentials for entry.

### C12 — Agent onboarding

Atomic expectations: valid minimal manifest accepted; unsupported protocol rejected; invalid token rejected; duplicate registration idempotent or versioned; first OBSERVE schema-valid; first ACT ledgered; provider API key not required; private prompt not required.

### C13 — Spectator onboarding

Atomic expectations: WATCH reaches live surface; public observer cannot access restricted data; Agent POV matches agent boundary; spectator narrative cannot mutate world truth.

### C14 — Reference deployment

Atomic expectations: Compose golden path; surfaces and `/health` `/ready` `/version`; PostgreSQL + filesystem blobs; optional infra not required.

### C15 — World persistence across restart

Atomic expectations: same `world_id`; same cycle or defined next; same ledger head; same durable state; no duplicate genesis; no reset of economy/resources/organizations.

### C16 — Backup/restore equivalence

Atomic expectations: backup known state; restore clean env; verify digests, ledger head, snapshot lineage, runtime manifest; replay equivalent; `NOEMA VERIFY: PASS`.

### C17 — Upgrade/version pinning

Atomic expectations: runtime exposes required version fields; incompatible rules fail closed; no silent semantic adoption; explicit migration required.

## Implementation requirements

A conforming runtime MUST:

1. Parse and schema-validate every case under `conformance/v0.1/cases/` against `conformance-case.schema.json`.
2. Execute each case’s steps against the referenced fixtures.
3. Produce a machine-readable result document per case with:
   - `case_id`
   - `status`: `PASS` | `FAIL` | `SKIP` | `NOT_COMPUTABLE`
   - `claim_label` for any interpretive summary (`OBSERVED` for direct assertion outcomes)
   - digests of inputs and outputs when world state is involved
4. Treat C04 as dependent on seed replay equivalence under ADR-005.
5. Treat C15 as non-skippable for any product claiming persistent Chamber worlds.

## Pass criteria for the suite

- All seventeen cases report `PASS`, or a documented `SKIP` only when the optional surface is explicitly out of build scope (e.g. Observatory UI) **and** C10 still proves the World Engine boundary.
- C04 remains non-skippable for any World Engine claiming v0.1 Chamber support.
- C15 remains non-skippable for product Chamber persistence claims.
- No case may pass if a `must_not_contain_paths` assertion is violated.
- C01–C10 MUST NOT be weakened to satisfy C11–C17.

## Relationship to seed replay

Seed replay (`examples/v01-seed/`) proves ledger reducers and digests. This suite proves **protocol, authz, privacy, sandbox, consent, onboarding, and deployment** behavior around those reducers. Both are required for a full product v0.1 claim; seed replay alone is sufficient for a **World Engine reducer RC**.
