## Implementation requirements

A conforming runtime MUST:

1. Parse and schema-validate every case under `conformance/v0.1/cases/` against `conformance-case.schema.json`.
2. Execute each case’s steps against the referenced fixtures.
3. Produce a machine-readable result document per case with:
   - `case_id`
   - `status`: `PASS` | `FAIL` | `SKIP` | `NOT_COMPUTABLE`
   - `claim_label` for any interpretive summary (`OBSERVED` for direct assertion outcomes)
   - digests of inputs and outputs when world state is involved
4. Treat C04 as dependent on seed replay equivalence under ADR-005.

## Pass criteria for the suite

- All ten cases report `PASS`, or a documented `SKIP` only when the optional surface is explicitly out of build scope (e.g. Observatory UI) **and** C10 still proves the World Engine boundary.
- C04 remains non-skippable for any World Engine claiming v0.1 Chamber support.
- No case may pass if a `must_not_contain_paths` assertion is violated.

## Relationship to seed replay

Seed replay (`examples/v01-seed/`) proves ledger reducers and digests. This suite proves **protocol, authz, privacy, sandbox, and consent** behavior around those reducers. Both are required for a full product v0.1 claim; seed replay alone is sufficient for a **World Engine reducer RC**.
