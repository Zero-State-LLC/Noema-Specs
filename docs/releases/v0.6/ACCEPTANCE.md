# v0.6 Deep Time: Acceptance

1. Prior suites C/F/O/S/L/P and RFC-0003 remain green.
2. Lore is never treated as canonical world truth.
3. Historical layers (ledger, state, evidence, belief, presentation) remain separate.
4. Institutions have explicit origin, practices, lifecycle, and succession mechanism.
5. Founder departure does not auto-delete institutions that survive participants.
6. Succession outcomes are deterministic and recorded.
7. Dormancy/dissolution retain addressable history.
8. Revival/successor identity is explicit (`SAME_ENTITY_EVOLVED` / `SUCCESSOR_ENTITY` / `NEW_ENTITY`).
9. Artifacts declare `claims_are_not_world_truth`.
10. Integrity DESTROYED preserves existence fact.
11. Evidence decay never mutates canonical ledger.
12. Conflicting claims remain CONTESTED without forced resolution.
13. Reconstruction forbids narrative invention.
14. Archaeology does not expose hidden ledger history.
15. Canonical IDs immutable under renaming.
16. World scars derive from event evidence.
17. Inheritance is explicit, never implicit.
18. Simple PLAY/WATCH projections do not require Deep Time jargon.
19. Simple and advanced views share the same subject IDs.
20. No runtime Deep Time engine is added to this repository.
21. Semantic lineage is explicit and machine-readable; derived meaning never becomes canonical ledger truth.
22. Canonical machine IDs never mutate when cultural or display names change.
23. Historical geography records prior states without rewriting the canonical ledger.
24. World scars derive from ledgered events and carry an explicit domain and visibility.
25. Inherited institutional identity is explicit (`SAME_ENTITY_EVOLVED` / `SUCCESSOR_ENTITY` / `NEW_ENTITY`).
26. Historical snapshots remain separate from canonical state; a snapshot never substitutes for the ledger.
27. PLAY projections expose Deep Time subjects without requiring Deep Time jargon.
28. WATCH timeline projections carry no hidden state and no research-only scalars.
29. STUDY longitudinal questions are answered from ledgered evidence and keep explicit claim labels.
30. Lore never overrides canonical evidence, and Deep Time provenance reuses RFC-0003 canonicalization.

### Genesis (admin-only)

G1. Same Genesis inputs reproduce the same Cycle 0 world.
G2. Different valid seeds can produce different valid starts (same profile/seeds).
G3. Cycle 0 passes ordinary world validation (`ordinary_world_valid`).
G4. Genesis does not determine future player outcomes; Story Seeds do not script full history.
G5. Initial history produces meaningful starting opportunities (≥3).
G6. Players do not receive hidden historical truth / Genesis config automatically.
G7. Artifacts/history use existing Deep Time contracts.
G8. Genesis requires no separate runtime service, workers, DB, or public APIs.
G9. Only authorized admin/operator may invoke Genesis; players/agents/spectators/researchers cannot modify Genesis config.
G10. Preview before activation; regeneration with claim-bearing input change creates new `genesis_id`.
G11. Activation freezes Genesis configuration; cannot rerun on active world (new run = new world).
G12. Ordinary PLAY requires no Genesis knowledge.
