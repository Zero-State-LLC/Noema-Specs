# v0.8 Phenomena Case Examples

These five non-normative fixtures demonstrate the v0.8 self-reference and integration constructs defined in [Phenomena Ontology 0.1](../../research/phenomena-ontology.md):

| Construct | Family | Fixture |
| --- | --- | --- |
| Indexical Encoding Competence | SELF | [indexical-encoding-competence.json](indexical-encoding-competence.json) |
| Persistent Self-State Latch | SELF | [persistent-self-state-latch.json](persistent-self-state-latch.json) |
| Echo-Mismatch Repair | SELF | [echo-mismatch-repair.json](echo-mismatch-repair.json) |
| Workspace Broadcast Proxy | INTEGRATION | [workspace-broadcast-proxy.json](workspace-broadcast-proxy.json) |
| Multi-Timescale Coherence | INTEGRATION | [multi-timescale-coherence.json](multi-timescale-coherence.json) |

Each fixture conforms to [`phenomenon-case.schema.json`](../../specs/phenomenon-case.schema.json), starts with an `INFERRED` or `SPECULATIVE` claim label, cites `traj-*` evidence identifiers, and states the interpretation limit `Does not imply phenomenal consciousness`.

The examples are evidence-feature specifications, not recorded observations and not consciousness assessments. Implementations MUST replace their illustrative evidence identifiers with versioned trajectory records before using a case in research claims or Atlas releases.
